# File Upload with Cloudflare R2

## Overview

Add file and image upload functionality using Cloudflare R2 storage.

## Requirements

- Create upload API route for R2
- Stick to lib/db/items.ts for prisma/db functions
- Create FileUpload component with drag-and-drop
- Update create item modal to use FileUpload for file/image types
- Delete files from R2 when items are deleted
- Create download proxy API route (avoids CORS issues)
- Add download button in ItemDrawer for file types
- Show upload progress indicator
- Display image preview for images, file info for files

## File Constraints

| Type   | Max Size | Extensions                                            |
| ------ | -------- | ----------------------------------------------------- |
| Images | 5 MB     | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`      |
| Files  | 5 MB (was 10 MB; capped for now) | `.pdf`, `.txt`, `.md`, `.json`, `.yaml`, `.yml`, `.xml`, `.csv`, `.toml`, `.ini` |

- Generate uuid as the file keys for data in neon datbaase & the storage database
- Sanitize the file names so there're no special characters on the file name
- Use short-lived signed direct url to upload or download form the cloudflare instead of going through vercel

## MIME Types

**Images:**
- `image/png`
- `image/jpeg`
- `image/gif`
- `image/webp`
- `image/svg+xml`

**Files:**
- `application/pdf`
- `text/plain`
- `text/markdown`
- `application/json`
- `application/x-yaml`, `text/yaml`
- `application/xml`, `text/xml`
- `text/csv`
- `application/toml`
- `text/plain` (for `.ini`)

## Implementation decisions (2026-10-08)

Settled while building; `context/current-feature.md` has the full requirements.

**Upload**
- Browser → R2 directly through a short-lived signed PUT link (5 minutes): a Vercel function body is capped at 4.5 MB. The file's exact size and type are signed in, so R2 refuses anything else. The "upload API route" became a signing step in the `createItem` action.
- The item is saved first; `uploadItemFile` then checks the file, rate limits (`upload`, 30 per hour), signs the link and writes the file details. If that step fails, the item is kept without a file and the dialog says why.
- Progress bar from XHR; the upload gives up after 1 minute.
- Missing `R2_*` settings are caught before the client is built: "an unknown error occurred with file uploads".

**Keys and names**
- Key: `users/{userId}/{uuid}{ext}`, built on the server only. Unique by uuid; the extension and a real `Content-Type` are kept so the bucket stays readable. The file name is never part of the key.
- Sanitised file name stored separately, for display and the download header (UTF-8 names kept via `filename*`).
- Every storage call is scoped to the user: a key outside `users/{userId}/` is refused.

**Validation**
- The extension must be allowed; the browser's MIME type must fit it or be blank (browsers report none for `.toml` and often `.yaml`/`.md`). The stored type always comes from the extension.
- Empty files are allowed. Checked in the browser (toast) and again on the server.

**Download**
- Not a signed direct link: files stream through `GET /api/items/[id]/file`, so every response carries the owner check, a sandbox CSP and `nosniff` (an SVG opened directly can't run script), and `private, no-store`. Streamed responses aren't held to Vercel's 4.5 MB limit.
- Images show inline (text fallback if they can't load); `?download=1` forces a download. Copy is hidden for file and image items.

**Other**
- `proxy.ts` now covers `/api/*` except `/api/auth/*`, answering signed-out calls with a JSON 401.
- Deleting an item deletes its R2 object after the row (a failed R2 delete is only logged).
