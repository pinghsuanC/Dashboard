# Refactor types into types/

- move every exported type into `src/types/`, one file per area, so shapes have one predictable home
- no behaviour change: only where types are defined and imported from

# Layout

- `types/items.ts`: ItemSummary, ItemDetail, ItemRowType, ItemCounts, ItemUpdate, ItemCollectionRef, ItemDetailResult, ItemDrawerLoad, EditableItemField, ItemTypeDefinition
- `types/collections.ts`: SessionCollection, CollectionSummary, CollectionStats, SidebarCollection, SidebarCollections
- `types/session.ts`: UserSession, CurrentUser, ItemStats
- `types/auth.ts`: ChangePasswordResult, RegisterResult, VerifyResult, VerifyNotice, ResetResult, ResetTokenStatus, RateLimitResult
- `types/email.ts`: EmailTemplate
- `types/forms.ts` and `types/next-auth.d.ts` stay as they are
- no `index.ts` barrel: import each file directly, like `lib/constants/`

# Exceptions

- types calculated from a constant stay beside it: `RateLimitPolicy` (`keyof typeof RATE_LIMITS`) and `Flag` (from `FLAGS`)
- internal, unexported types (e.g. Prisma row payloads in `lib/db/items.ts`) stay where they are used

# Rules

- `types/` files import no runtime code: no Prisma, no constants values, only `import type` between type files
- `lib/db`, `lib/`, services and components import shapes from `@/types/...`; components never import from `@/lib/db`
- update `CLAUDE.md` with the rule and the layout

# Do it by following steps

- list every exported type and its importers
- write the boundary rules as tests first and see them fail
- move one area at a time, update importers, keep tests green
- break each new rule once to prove its test can fail
