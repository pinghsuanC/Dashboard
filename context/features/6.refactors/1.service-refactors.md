# Added during the work (scope beyond the brief)

## All database access, not only writes

- every Prisma call goes through the service folder, reads included, not just the CRUD writes
- `services/prisma.ts` builds the one client; only `services/` and `lib/db/` may import it
- `lib/db/` keeps the interface: builds queries, checks the session user, shapes results
- profile check: Item, Collection and User queries always include the session user, so another user's id finds nothing

## Auth service

- `services/auth/` holds the session check (moved from `lib/db/current-user.ts`), the Auth.js adapter, and the database side of sign-in, register, password change, verification and reset
- split into files (`session`, `adapter`, `users`, `tokens`) so the imports can't loop
- `changePassword` and `deleteAccount` take the user from the session, never an argument

## lib/ cleanup

- group `lib/` by area: `auth/`, `items/`, `session/`, `helpers/` (generic helpers), next to `db/` and `constants/`
- only `utils.ts` stays at the root (shadcn's `components.json` points at it)
- delete `lib/mock-data.ts` from the app; its data moves to `prisma/seed-data.ts` for the seed

## Guardrails

- a boundary test enforces the layout: who may import the database client, Resend and Upstash, that `services/` never imports `lib/db/`, and the `lib/` root
- every service is `server-only` (except `prisma.ts`, which the seed loads in plain Node)
- services hold no user-facing text; rate limit wording moves to `lib/auth/rate-limit-messages.ts`
